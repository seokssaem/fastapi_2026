스웨거 UI 구조 설명

① 엔드포인트 목록
GET /menus 전체 메뉴 목록 반환
POST /menus 새 메뉴 등록
② Parameters (경로/쿼리 파라미터)
URL에 포함되는 값들
예: /menus/1 → menu_id = 1
예: /menus?page=2 → page = 2
이 엔드포인트는 파라미터 없음
③ Request Body (요청 바디)
POST/PATCH 때 클라이언트가 서버로 보내는 JSON
Try it out 클릭 후 직접 입력 가능
{ "name": "김치찌개", "category": "한식", "price": 9000 }
④ Responses (응답 코드 목록)
서버가 돌려줄 수 있는 HTTP 상태코드 목록
여기서 헷갈리는 부분이 바로 이 아래!
201 성공 시 응답 예시 (response_model 기반 자동 생성)
{ "id": 5, "name": "김치찌개", "category": "한식", "price": 9000, "like": 0 }
422 유효성 검사 실패 — FastAPI 자동 생성, 항상 존재
← 이게 "응답 결과 밑에 또 나오는 것"의 정체!
실제 에러가 아니라 "이런 에러가 날 수 있다"는 명세
422가 항상 나오는 이유
FastAPI + Pydantic 조합은 요청 데이터를 자동으로 검증함.
타입 불일치, 필수 필드 누락 등 → 422 자동 반환.
그래서 모든 엔드포인트에 422 명세가 자동으로 붙음.
Responses 섹션 구조 요약
실제 응답 (Execute 후 나오는 것) → 서버가 지금 막 돌려준 진짜 데이터 Responses 명세 (그 아래 항상 있는 것) → "이 API는 이런 응답을 줄 수 있다"는 설명서 → 201 : 성공했을 때 구조 → 422 : 잘못된 요청일 때 구조 ← 이게 헷갈렸던 부분
